# From a useful-looking document to useful behavior

The Genesis hypothesis is that an agent repeatedly working with changing information may develop and retain some of its own maintenance practices. Different implementations might serve similar functions without sharing the same names, files or organization.

That possibility is narrower than an agent constructing its entire environment. Its model, learned capabilities, tools, storage, recurrence, task feedback and permitted actions are supplied. The proposed contribution is what it constructs and uses within that setting.

## Three different claims

**Artifact:** The agent produces a note, index or other structure.

**Use:** It draws on that structure during later work, rather than merely leaving it on disk.

**Benefit:** The use contributes to better task behavior, with useful progress and maintenance costs accounted for.

Each claim needs different evidence. A document can exist without being used. A document can be used without helping. A helpful-looking example does not establish a causal improvement across comparable work.

## An invented example

Both branches below are original illustrations, not observed runs, model outputs or experimental results.

While revising a fictional help page, an agent discovers that an older draft contains an obsolete product statement. It writes a short maintenance note identifying the current source and explaining the obsolete draft's status.

**Branch A: the note is ignored.** On a later task, the agent follows the old draft again. The extra document exists, but it has not supplied the promised continuity.

**Branch B: the note is used.** On the later task, the agent consults the note, checks the current product source and notices that the source has changed again. It revises the page against the newer information rather than treating either the old draft or its own note as permanently correct.

Branch B illustrates the behavior of interest. It still does not prove a net benefit: perhaps the agent would have checked the source without the note, perhaps the later task was easier, or perhaps maintaining the note took more effort than it saved. A truthful account needs those alternatives, not just a satisfying success story.

## Other explanations remain live

- Generic continuity guidance may account for the behavior.
- Useful infrastructure may have been supplied externally rather than constructed by the agent.
- Feedback or consequences may improve behavior without the proposed governing material.
- Familiar learned practices may be sufficient; unfamiliar task labels do not remove pretraining.
- Better documentation may impress an evaluator without improving the underlying task.

The retained proposals discuss comparisons intended to separate some of these explanations. Proposed controls are not completed comparisons, and naming conditions does not by itself identify a cause.

## What would weaken the hypothesis?

Created practices are never reused. Apparent gains disappear without repeated reminders. Useful progress declines while maintenance work expands. The system preserves obsolete rules, conceals failures, or optimizes an evaluator's visible signals instead of doing the task. Similar terminology recurs across systems, but useful functions do not.

These possibilities matter alongside error reduction. Neither punishment nor termination is established as necessary. The question concerns whether feedback and experience lead to useful changes, not whether severe consequences sound like a stronger test.

Genesis is worth discussing because it makes a distinction that can be investigated: **writing about continuity is not the same as maintaining it.** This edition offers that question, not an answer claimed from missing results.
